# XP12 AI ATC — план проекта

Бесплатный аналог SayIntentions для X-Plane 12: голосовой диспетчер, который знает реальные данные аэропорта, ведёт по фазам полёта и сам выходит на связь.

> Документ — стартовое ТЗ для Claude Code. Детали API и форматов файлов **сверять с официальной документацией** (developer.x-plane.com) и с реальными файлами в установке X-Plane, а не с этим текстом.

---

## Ключевой принцип

**Решения принимает детерминированная логика, LLM только по краям.**

- Что сказать (какая ВПП, какой маршрут, какая высота, когда хендофф) → код, данные X-Plane, машина состояний.
- Как понять пилота → STT + LLM разбирает фразу в структуру (JSON).
- Как сказать → шаблоны фразеологии (по желанию LLM их «оживляет», но без права менять цифры и имена).

LLM никогда не придумывает частоты, рулёжки, ВПП, высоты.

## Стек (всё бесплатно)

| Задача | Инструмент |
|---|---|
| Язык | Python 3.11+ |
| Связь с симом | Встроенный Web API X-Plane 12 (REST + WebSocket на localhost) |
| Распознавание речи | faster-whisper (локально) |
| Синтез речи | Piper TTS (локально), разные голоса на позиции |
| Разбор фраз пилота | Gemini Flash (free tier) или локальная модель через Ollama — за общим интерфейсом |
| Граф и поиск пути | networkx (`astar_path`) |
| PTT | глобальная горячая клавиша (pynput / keyboard) или кнопка джойстика через X-Plane command |
| Аудио | sounddevice |

Gemini free tier: лимиты меняются, данные могут использоваться для обучения. LLM-слой делать сменным.

## Данные из X-Plane

**Датарефы (через Web API):**
позиция (lat/lon/elev), AGL, курс, путевая и приборная скорость, вертикальная скорость, on_ground, COM1/COM2 активная частота, код и режим транспондера, тормоз стояночный, работа двигателей, ветер/давление у самолёта, TCAS-цели (для трафика, позже).

**Файлы:**
- `apt.dat` — глобальный в `Global Scenery/Global Airports/Earth nav data/`, кастомные в `Custom Scenery/*/Earth nav data/` (кастомная сцена перекрывает глобальную для того же ICAO). Нужные коды строк (проверить по спеке формата):
  - `1` — заголовок аэропорта, `100` — ВПП
  - `1201` — узел рулёжки, `1202` — ребро (имя, one-way, тип), `1204` — active zone (hold short)
  - `1300` — стоянки/гейты
  - `1050–1056` — частоты (ATIS, unicom, delivery, ground, tower, approach, departure)
- Навигация: `earth_fix.dat`, `earth_nav.dat`, `earth_awy.dat` (дефолтные + `Custom Data`, если есть).
- `CIFP/<ICAO>.dat` — SID, STAR, заходы.
- Погода: из датарефов сима; METAR по сети — опционально.

## Фазы полёта (машина состояний)

`PARKED → CLEARANCE → PUSH/START → TAXI_OUT → HOLDING → TAKEOFF → DEPARTURE → ENROUTE → ARRIVAL → APPROACH → LANDING → TAXI_IN → PARKED`

Каждая фаза знает: активную позицию (Delivery/Ground/Tower/Departure/Center/Approach), её частоту, ожидаемые запросы пилота, допустимые указания.

Если пилот на частоте не той позиции, диспетчер молчит или говорит «wrong frequency, contact …».

---

## Проактивность (monitor)

Цикл раз в ~1 с проверяет правила и кладёт события в очередь. Примеры:

- оторвался и прошёл N футов → «contact Departure 124.35»
- достиг TOD → «descend and maintain …»
- отклонение от выданной высоты > 300 ft или курса > 20° → замечание
- пересёк hold short без разрешения → предупреждение
- освободил ВПП → «contact Ground …»
- пилот не ответил на передачу за ~10 с → повтор вызова
- свернул не на ту рулёжку → «you missed the turn …»

Правило решает **что**, phraseology — **как**. Не спамить: cooldown на каждое правило, не перебивать пилота во время PTT.

## Руление

1. Парсер apt.dat → `networkx.DiGraph` (узлы 1201, рёбра 1202, one-way учитывать).
2. Стоимость ребра = длина × штрафы (перрон, резкий поворот, ширина не подходит по типу ВС).
3. Старт: ближайший узел к позиции самолёта. Цель: точка ожидания у ВПП в работе (через 1204 / геометрию).
4. A* → список рёбер → свернуть в имена рулёжек, убрать мелкие соединители, схлопнуть повторы → «taxi via A, B, hold short 27L».
5. На прибытии маршрут строится **после** схода с ВПП.
6. Граф отсутствует или разорван → fallback: «taxi to runway 27L at your discretion» + лог.

ВПП в работе выбирается по ветру (минимальная попутная составляющая).

## Разбор фраз пилота

Whisper → текст (в `initial_prompt` подсовывать позывной, ICAO, имена рулёжек/фиксов текущего контекста).

LLM получает текст + контекст фазы и возвращает строго JSON, например:

```json
{
  "intent": "request_taxi",
  "callsign": "DLH4AB",
  "readback": {"runway": "27L", "hold_short": "27L"},
  "readback_ok": true,
  "unclear": false
}
```

Список intent'ов фиксированный (request_clearance, readback, request_pushback, request_taxi, ready_for_departure, check_in, request_descent, request_approach, report_position, say_again, …). Невалидный JSON или `unclear` → «say again».

## Этапы

### Этап 1 — MVP (один аэропорт)
- [ ] `sim_link`: подключение к Web API, подписка на датарефы, вывод SimState в консоль
- [ ] PTT → запись → faster-whisper → текст в консоль
- [ ] Piper: озвучка строки, 2–3 голоса
- [ ] Парсер apt.dat для одного ICAO: ВПП, частоты, стоянки, граф
- [ ] Delivery: IFR-клиренс (простой: destination, runway, initial altitude, squawk)
- [ ] Ground: руление по A* с hold short
- [ ] Tower: взлёт, хендофф на Departure
- [ ] intent_parser на Gemini с JSON-ответом
- [ ] Минимум проактива: хендоффы, повтор при молчании

### Этап 2 — полёт A→B
- [ ] Любой аэропорт, учёт кастомных сцен
- [ ] Выбор ВПП по ветру
- [ ] SID/STAR из CIFP, указания по высоте на маршруте
- [ ] Center: эшелон, снижение по TOD
- [ ] Approach: векторение на ILS, clearance на заход
- [ ] Посадка, сход, руление к стоянке
- [ ] Контроль отклонений (высота, курс, руление)
- [ ] Окно в симе или оверлей с текстом последней передачи

### Этап 3 — полировка
- [ ] ATIS
- [ ] Трафик по TCAS-целям (информация, сепарация на земле)
- [ ] VFR-сценарии
- [ ] Настройки: регион/фразеология (ICAO/FAA), голоса, клавиша PTT, выбор LLM

## Правила работы для ИИ-ассистента

- Начинать с этапа 1 по порядку, каждый пункт — проверяемый результат (скрипт, который можно запустить).
- Перед кодом с Web API и форматами файлов — свериться с документацией X-Plane и реальными файлами в установке.
- Для парсеров и taxi-логики писать тесты на фикстурах из реальных apt.dat.
- Логи всего: датарефы, фазы, распознанный текст, JSON от LLM, сказанное диспетчером.
- Секреты (API-ключи) только в `.env`, не в репо.
